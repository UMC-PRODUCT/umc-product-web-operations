# 상벌점 목록: 기수·지부·학교·파트와 검색

상벌점 관리 목록은 필터 네 개와 검색어로 `GET /api/v2/member/search`를 호출한다. 기수, 지부, 학교는 서로 다른 API에서 오고, 파트만 화면 고정 값이다. 지부는 API의 챕터다. `/api/v1/chapters`는 호출하지 않는다.

요청 경로는 클라이언트가 `/v1/...`, `/v2/...`로 보내고, 베이스 URL이 `/api`를 붙여 스펙 경로가 된다.

## 한눈에 보기

| 화면 | 데이터를 가져오는 곳 | 검색에 보내는 값 | 비었을 때 |
| --- | --- | --- | --- |
| 좌측 기수 전환 | `GET /api/v1/gisu` | `gisuId` | 기수 목록 조회가 끝나기 전에는 멤버 검색을 보내지 않음 |
| 지부 | `GET /api/v2/gisu`의 `chapters` | `chapterId` | 파라미터를 빼서 지부 전체 |
| 학교 | 같은 응답의 `schools` | `schoolId` | 파라미터를 빼서 학교 전체 |
| 파트 | 화면 고정 네 개 | `part` | 파라미터를 빼서 파트 전체 |
| 이름·닉네임 | 입력값 | `keyword` | 앞뒤 공백을 지운 값이 없으면 파라미터를 뺌 |

공통으로 `page`는 0부터, `size`는 10이다. 응답 `totalPages`가 2 이상이면 표 아래에 페이지 번호를 보여 준다. 화면 번호는 1부터라 요청할 때 1을 빼서 보낸다.

## 기수

기수는 상벌점 툴바가 아니라 좌측 사이드바 위 `ContextSwitcher`다. 관리 셸이 마운트되면 `SelectedGisuProvider`가 목록을 한 번 가져온다.

```
GET /api/v1/gisu?page={n}&size=20
```

- 응답은 `result.content[]`다. 항목의 `gisuId`, `generation`은 숫자 문자열로 올 수 있어서 양의 정수로 바꾼다. `generation`이 없으면 `gisu`를 쓴다.
- `isActive === true`인 항목만 활성 기수로 본다.
- `hasNext`가 참이면 다음 페이지를 이어서 가져온다. 한 페이지는 20건이고, 최대 10페이지까지다.
- React Query 키는 `["gisu", "list"]`다. `retry`는 꺼져 있고 `staleTime`은 60초다.

선택 규칙은 이 순서다.

1. 사용자가 고른 `gisuId`
2. 없으면 `isActive`인 기수
3. 그것도 없으면 목록의 첫 항목

전환 메뉴의 값은 `gisuId` 문자열이고, 라벨은 `11기`처럼 `generation`에 `기`를 붙인다. 목록이 오기 전에는 전환 메뉴를 그리지 않는다. 헤더 로고의 기수 숫자는 선택된 `generation`을 쓰고, 목록이 오기 전에만 `11`을 임시로 보여 준다.

고른 `gisuId`는 멤버 검색 쿼리로 들어간다. 기수가 바뀌면 지부 선택, 학교 선택, `page`를 비운다. 학교 회장단이라 학교가 잠겨 있으면 학교만 그대로 둔다.

기수 목록 조회가 끝나기 전에는 조직 조회와 멤버 검색을 시작하지 않는다. 목록 조회가 실패하면 `gisuId` 없이 검색하고, 지부·학교는 활성 기수 기준으로 조회한다.

## 지부와 학교

둘 다 기수 조직 API에서 온다. 지부 전용 목록 API는 쓰지 않는다.

```
GET /api/v2/gisu?id={gisuId}&includeChapter=true&includeSchool=true
```

선택된 `gisuId`가 없을 때만 `id` 대신 `active=true`를 보낸다. React Query 키는 `["gisu", "organization", gisuId]`이고 `retry`는 꺼져 있다.

응답 `result.gisus[]`에서 메뉴를 만든다.

- 지부: `chapters[].id`, `chapters[].name`. 검색 쿼리는 `chapterId`.
- 학교: `schools[].schoolId`, `schools[].schoolName`. 검색 쿼리는 `schoolId`.

같은 id는 한 번만 넣고, 이름이 없는 항목은 뺀다. 학교 목록이 채워져도 지부 메뉴에는 들어가지 않는다. `chapters`가 비어 있으면 지부 메뉴에는 **지부 전체**만 남는다.

각 메뉴의 첫 항목은 API 값이 아니다.

- `지부 전체`, `학교 전체`의 값은 화면 전용 `"all"`이다.
- 이 값을 고르거나 아직 고르지 않으면 선택값은 `null`이 되고, 해당 쿼리는 요청에서 빠진다.
- 닫힌 메뉴가 비어 있을 때 보이는 문구도 같은 **지부 전체**, **학교 전체**다.

### 학교 회장단 고정

`GET /api/v2/member/me`로 만든 세션의 범위가 `SCHOOL`이고, 역할에 `SCHOOL_PRESIDENT` 또는 `SCHOOL_VICE_PRESIDENT`가 있으며 `schoolId`가 있을 때만 잠근다.

- 지부는 **지부 전체**로 고정하고 `chapterId`를 보내지 않는다.
- 학교는 세션의 `schoolId`로 고정하고 그 값을 `schoolId`로 보낸다. 조직 응답에 그 학교가 없으면 세션의 `schoolName`을 옵션에 덧붙인다.
- 두 `Select`는 `disabled`다.

총괄, 중앙 운영진, 지부장처럼 더 넓은 역할이 있으면 범위가 `SCHOOL`이 아니므로 잠그지 않는다. `SCHOOL_ETC_ADMIN`만 있는 교내 운영진도 잠그지 않는다.

## 파트

파트를 내려 주는 목록 API는 없다. 툴바에 네 개만 고정되어 있다.

| 화면 | 검색 `part` |
| --- | --- |
| 파트 전체 | 보내지 않음 |
| PM | `PLAN` |
| Design | `DESIGN` |
| Web PE | `WEB_PRODUCT_ENGINEER` |
| Mobile PE | `MOBILE_PRODUCT_ENGINEER` |

멤버 검색이 허용하는 값은 이 네 개 외에도 `WEB`, `ANDROID`, `IOS`, `NODEJS`, `SPRINGBOOT`, `ADMIN`이 있다. 필터 메뉴에는 없고, 목록에 그 파트가 오면 아래처럼 태그로만 보여 준다.

| 응답 `part` | 태그 | 표시 이름 |
| --- | --- | --- |
| `PLAN`, `ADMIN` | PM | PM, Admin |
| `DESIGN` | Design | Design |
| `WEB`, `WEB_PRODUCT_ENGINEER`, `NODEJS`, `SPRINGBOOT` | Web PE | Web, Web PE, Node.js, Spring |
| `ANDROID`, `IOS`, `MOBILE_PRODUCT_ENGINEER` | Mobile PE | Android, iOS, Mobile PE |

현재 챌린저 파트가 없으면 챌린저 기록의 첫 파트를 쓴다. 둘 다 없으면 PM 태그를 보여 주고 파트 이름은 비운다.

## 검색어와 디바운스

검색 칸은 `이름 · 닉네임으로 검색할 수 있어요`이고, 지우기 버튼이 있다. 입력값은 `query`에 바로 저장되어 칸의 글자는 지연 없이 바뀐다.

요청에 쓰는 값은 따로 둔다.

```ts
const keyword = useDebouncedValue(query.trim(), 300)
```

- 지연은 300ms다.
- 입력이 바뀔 때마다 이전 타이머를 취소하고 다시 잰다. 타이핑이 멈춘 뒤 한 번만 `keyword`가 바뀌고, 그때 React Query 키가 바뀌어 `GET /api/v2/member/search`가 나간다.
- 첫 화면의 초기값은 빈 문자열이라 300ms를 기다리지 않고 바로 목록을 조회한다.
- `query.trim()` 결과가 같으면, 예를 들어 `"김"` 뒤에 공백만 더해도, 효과 의존성이 그대로라 추가 요청이 없다.
- 앞뒤 공백을 지운 값이 빈 문자열이면 `keyword` 파라미터를 빼서 이름 조건 없는 목록을 조회한다.
- 지우기도 같은 300ms를 기다린 뒤 조건 없는 목록으로 돌아간다.

결과 없음 문구는 칸에 치는 중인 `query`가 아니라, 실제로 요청한 `keyword`를 쓴다. 그래서 이전 결과가 남아 있는 동안 문구가 아직 안 끝난 입력과 어긋나지 않는다. `keyword`가 있으면 `'검색어' 님을 찾을 수 없어요`, 없으면 `조건에 맞는 구성원을 찾을 수 없어요`다.

필터를 바꾸거나 검색 칸이 바뀔 때 `page`를 0으로 되돌린다. 검색 칸은 글자마다 즉시 0으로 맞추지만, 요청은 디바운스된 `keyword`가 바뀐 뒤에만 다시 나간다. 페이지 번호를 누르면 그 페이지를 다시 조회하고, 목록 상단으로 스크롤을 올린다.

## 목록 요청

기수 목록 조회가 끝난 뒤 아래를 호출한다.

```
GET /api/v2/member/search?page={page}&size=10
```

값이 있는 것만 붙인다.

- `keyword`: 디바운스 후 공백을 제거한 검색어
- `gisuId`: 선택된 기수 id
- `part`: 화면 파트를 API 값으로 바꾼 것
- `chapterId`: 선택된 지부 id
- `schoolId`: 선택된 학교 id

React Query 키는 `["members", "search", { keyword, gisuId, part, chapterId, schoolId, page, size }]`다. 키 안의 `part`는 화면 값(`pm` 등)이고, 실제 요청의 `part`는 `PLAN` 같은 API 값이다. `retry`는 꺼져 있다. 실패 후 다시 시도는 네트워크 오류 화면의 재시도 버튼만 한다. 그 버튼은 같은 조건으로 `refetch`한다.

호출자에게 챌린저 기록이 없으면 이 검색은 403이다. 그 경우 기존 권한 없음 UI를 보여 준다.

## 표에 그리는 방식

응답은 `result.page.content[]`다. 한 행은 `toPointsMember`로 바꾼다.

| 열 | 응답 | 화면 |
| --- | --- | --- |
| 구성원 | `name`, `nickname` | `이름 / 닉네임`. 행을 누르면 상세로 이동 |
| 학교 | `schoolName`, 없으면 첫 챌린저 기록의 `schoolName` | 학교명 그대로 |
| 파트 | `currentChallenger.part`, 없으면 첫 기록의 `part` | 위 파트 태그 |
| 기수 | `currentChallenger.generation`, 없으면 첫 기록의 `gisu` | `11기` 형식. 없으면 빈 칸 |
| 운영 역할 | `isAdminInActiveGisu`가 참일 때 기록의 첫 `challengerRoleType` | 아래 표 |
| 상태 | 없음 | 항상 `활동` |
| 상벌점 부여하기 | `currentChallenger.challengerId` | `/activity/points/{memberId}?challengerId=` |

운영 역할은 활성 기수 운영진일 때만 기록에서 읽고, 아니면 챌린저다.

| `challengerRoleType` | 표시 |
| --- | --- |
| `CHAPTER_PRESIDENT` | 지부장 |
| `CENTRAL_PRESIDENT`, `CENTRAL_VICE_PRESIDENT`, `CENTRAL_OPERATING_TEAM_MEMBER`, `CENTRAL_EDUCATION_TEAM_MEMBER` | 중앙 운영진 |
| `SCHOOL_PRESIDENT`, `SCHOOL_VICE_PRESIDENT` | 회장단 |
| `SCHOOL_PART_LEADER`, `SCHOOL_ETC_ADMIN` | 교내 운영진 |
| 그 외, 또는 활성 기수 운영진이 아님 | 챌린저 |

상세로 갈 때 `challengerId`가 없으면 쿼리 없이 `memberId`만 넘어간다.

## 로딩, 오류, 빈 목록

표는 아래 순서대로 기존 UI 중 하나만 보여 준다.

1. 로딩이면 스켈레톤. 멤버 검색이 아직 끝나지 않았거나, 오류 난 요청을 다시 가져오는 중이다. 기수 목록을 기다리는 동안에도 검색 쿼리가 꺼져 있어 이 로딩으로 보인다. 403은 로딩으로 치지 않는다.
2. 403이면 권한 없음.
3. 그 외 오류이고 재시도 중이 아니면 네트워크 오류와 재시도.
4. `content`가 비었으면 결과 없음.
5. 아니면 표.

이미 목록이 있는 상태에서 필터나 페이지가 바뀌면, 오류가 아닌 한 스켈레톤으로 갈아타지 않고 이전 행을 유지한다. 새 응답이 오면 행을 바꾼다. `totalPages`가 2 이상이고 행이 있을 때만 표 아래에 페이지 번호를 둔다.
