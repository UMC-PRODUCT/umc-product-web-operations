## 🎞️ 주요 코드 설명

> 설명이 필요한 코드 위주로 작성해주세요

### 패키지 의존과 import

```TypeScript
// package.json
"@umc-product/auth-client": "0.1.3"

// 앱 코드
import { createAuthClient, resolveAuthConfig } from "@umc-product/auth-client"
import { DevLoginForm } from "@umc-product/auth-client/react" // login.tsx DEV only
```

- `src/lib/auth-client/**` 삭제. eslint는 `@umc-product/auth-client` / `.../react`만 허용합니다.
- `0.1.0`·`0.1.2`는 깨진 빌드이므로 쓰지 않습니다 (`>=0.1.3`).

### 앱 어댑터 — origin 표 + optional `stageUrls`

```TypeScript
// src/shared/auth/resolve-sso-env.ts
return resolveAuthConfig({
  clientIds: CLIENT_ID,
  local: { authAppUrl: runtime.authAppUrl, loginMode: runtime.loginMode },
  origin,
  origins: ADMIN_ORIGINS,
  stageUrls: runtime.stageUrls, // 평소 생략. 유사시만
})
```

- 평소 API·Auth URL은 패키지 `SSO_STAGES`를 씁니다.
- 인프라 URL이 바뀌었는데 패키지 배포 전이거나, 특정 앱만 임시 엔드포인트가 필요할 때만 `stageUrls`로 덮어씁니다.
- localhost의 `VITE_AUTH_APP_URL`은 기존처럼 `local.authAppUrl`이 `stageUrls`보다 우선합니다.

### HTTP 역할 분리

| 구분 | 담당 |
| ---- | ---- |
| SSO 프로토콜 (authorize/token/renew/logout) | 패키지 `createAuthClient` 내부 fetch |
| 인증 fetch (`createApiFetch`) | 패키지 (Bearer + 401 복구) |
| 서비스·도메인 API | 앱 axios (`src/shared/api/client.ts`) — 토큰/갱신만 패키지에 위임 |

- SSO를 axios로 다시 구현하지 않습니다.
- 도메인 401 재시도 제외는 `isAuthEndpoint(url)`로 판별합니다.
